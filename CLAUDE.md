# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Benchwarmer Analytics is a hockey analytics platform for exploring NHL data, line combinations, and player performance. It ingests data from MoneyPuck, the NHL API and ESPN (injuries, transactions, sportsbook lines for model benchmarking) and presents it through a web interface with visualizations.

**Status:** In production at https://benchwarmer.reecerose.com (Vercel + Neon).

## Tech Stack

- **App:** TanStack Start (React 19, TypeScript, Vite), TanStack Router/Query, shadcn/ui, Tailwind CSS
- **Server:** TanStack Start server routes under `/api/*`, deployed to Vercel via Nitro
- **Database:** Neon Postgres 18, Drizzle ORM (`drizzle-orm/neon-http` in request handlers), migrations via `drizzle-kit`
- **Ingestion:** MoneyPuck CSVs + NHL API + ESPN (unofficial, zod-checked) via Vercel Cron routes (`/api/cron/*`) and a local backfill CLI; node-postgres on the direct connection

## Commands

All commands run from `app/`:

```bash
npm ci                  # install
npm run dev             # dev server on http://localhost:3000
npm run build           # production build (Nitro; Vercel output when built on Vercel) + typecheck
npm run start           # run the production build locally
npm run lint
npm run typecheck       # needs src/routeTree.gen.ts, generated by `npm run dev` or `npm run build`
npm test                # Vitest (src/**/*.test.ts)

npm run db:generate     # generate a migration from src/server/db/schema.ts
npm run db:migrate      # apply migrations (uses DATABASE_URL_UNPOOLED, else DATABASE_URL)
npm run db:check        # check migration consistency
npm run db:studio
npm run backfill -- --yes   # load 2008 → current (resumable; see docs/INGESTION_NOTES.md)
```

Scratch local database (throwaway, no volume):

```bash
docker run -d --rm --name bw-pg18-scratch -e POSTGRES_PASSWORD=scratch -e POSTGRES_DB=benchwarmer -p 55432:5432 postgres:18
DATABASE_URL=postgresql://postgres:scratch@localhost:55432/benchwarmer npm run db:migrate
```

## Key Configuration

- **Environment** (see `app/.env.example`): `DATABASE_URL` (pooled), `DATABASE_URL_UNPOOLED` (direct, for migrations and backfill), `CRON_SECRET`. Locally, put them in `.env.local` at the repo root (where `neon link` writes it) or in `app/.env.local` (which takes precedence).
- `getDb()` uses neon-http for Neon URLs and node-postgres for localhost URLs, so a scratch docker Postgres works in development.
- Rendering: routes are client-rendered unless they set `ssr: true`. The root layout (header, scores strip, footer) and the homepage are server-rendered, so components they render must not touch `window`/`localStorage` or theme state during render (team logos switch variants with the `dark:` class instead). An SSR route's loader prefetches its queries with `prefetchForSsr()` (`src/lib/ssr-prefetch.ts`), using the same query options as its hooks; `@tanstack/react-router-ssr-query` sends the results to the browser. During SSR, `src/lib/api.ts` fetches the public URL, so it goes through the CDN cache. Client-only routes may use `window`/`localStorage` freely.
- `/api` routes must set an explicit handler for each method they support, plus `ANY: methodNotAllowed`, so wrong-method requests don't fall through to the HTML shell.
- API handlers live in `src/server/api/<group>.ts` and are wrapped with `apiHandler(CacheTier.x, fn)` (query parsing, `{ error, code }` errors, CDN cache header). GET handlers are read-only. Use `round()` from `format.ts` for rounded outputs (banker's rounding on the value's decimal form).

## Database

- Drizzle owns the schema. Change `src/server/db/schema.ts`, then `npm run db:generate`. Never edit an applied migration.
- Table/column names are snake_case and keep some odd spellings (e.g. `went_to_o_t`, `i_f_x_freeze`) that queries and raw SQL depend on. See `docs/SCHEMA_NOTES.md`.
- Materialized views (`chemistry_pairs`, `season_percentiles`) are `.existing()` in the schema; their DDL is hand-written SQL in migrations. Refresh with `REFRESH MATERIALIZED VIEW CONCURRENTLY`.
- `numeric` columns are mapped to JS numbers (`mode: "number"`). Ingestion writes exact decimal text instead (see `UpsertRow` in `src/server/ingestion/db.ts`).

## Ingestion

- MoneyPuck CSV field specs live in `src/server/ingestion/records.ts`. Importers copy same-named fields generically (`map.ts`) and hand-write only the exceptions.
- All writes go through `upsert()` (`db.ts`): batched `INSERT ... ON CONFLICT DO UPDATE ... WHERE ... IS DISTINCT FROM`, so re-runs write ~0 rows. Keep it that way: Neon cost depends on it.
- Every step runs inside `runStep()` so it's logged in `sync_runs`.
- Be polite to MoneyPuck: sequential downloads only.

## UI Changes

Before changing any UI (pages, components, charts, styles), read `docs/DESIGN_SYSTEM.md` and follow it: the "press box" colour rules, the `@/components/layout` building blocks, the patterns for tables, charts and two-team comparisons, and the checklist at the end. If a change adds a new pattern, update that doc in the same change.

## Code Style

### Frontend (React/TypeScript)

- **No JSX comments**: Do not use `{/* comment */}` syntax in JSX. If a comment is truly needed, use regular JS comments outside of JSX or refactor to make the code self-documenting.
- Use `@/` path-alias imports, not relative imports (enforced by ESLint).
